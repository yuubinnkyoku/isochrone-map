# 物理駅地点と IDW 標本の意味

## 結論

現在の物理駅データでは、`data/stations.json` の 1563 地点をすべて IDW 標本として使う。

`excludeFromIdw` は 1563 地点すべて `false` であるべきで、最適経路がその地点の鉄道設備から直接乗車するか、同じ論理駅の別構成駅へ歩くか、別駅へ歩くかは **IDW 除外条件ではない**。

## 補間している量

この地図で各座標 `x` に対応させたい量を、

```text
A(x) = 「x から出発し、許可された徒歩・鉄道・路線バスを使って
        08:18 までに学校へ到着できる最も遅い出発時刻」
```

とする。

物理駅地点 `x_i` に対する Yahoo!乗換案内 `flatlon` 検索は、まさにこの `A(x_i)` を問い合わせている。さらに全1563地点について Yahoo 側の最初の徒歩経路の `fromLat/fromLon` を確認し、要求座標から5m以内であることを検証している。

したがって、ある地点 `x_i` の最適経路が、

```text
x_i → 徒歩 → 別構成駅 / 別駅 → 鉄道 → … → 学校
```

だったとしても、その値は `x_i` からのアクセシビリティとして正しい。最初にどの鉄道設備から乗るかは、`A(x_i)` の定義を変えない。

## 旧データで除外が必要だった理由との違い

旧論理駅データでは駅名検索で得た「その駅を使う経路」の値を、ひとつの代表座標へ置いていた。そのため、駅名が同じでも設備位置が離れている場合や、代表座標から別経路へ歩いた方が有利な場合に、値と座標の対応が崩れることがあった。

その状況では「駅名検索の直接値」を IDW から外すことに意味があった。

現在は次の2点が変わっている。

1. N02-25 の路線別駅コードと代表座標を使い、異なる物理駅地点を1563点へ分離した。
2. 各物理地点を文字列の駅名ではなく `flatlon` の座標から再検索し、その地点からの unrestricted な最適経路へ値を置き換えた。

つまり旧除外が対処していた「値と座標の不一致」は、値そのものを exact-point アクセシビリティへ再計算した時点で解消している。

## first-rail 分類の用途

全1563地点の exact-point 監査では、最適経路の最初の鉄道乗車を次のように分類している。

- 当該物理地点自身から乗車: 976
- 同じ論理駅の別物理地点へ移動して乗車: 232
- 別駅へ移動して乗車: 343
- 最適経路で鉄道に乗らない: 12

この分類は、物理駅分離が経路選択へどう影響するかを見るための診断情報である。後3分類も `A(x_i)` の正当な値なので、それだけを理由に IDW から捨てない。

熊野前なら、都電荒川線側の物理地点から舎人ライナー側へ歩いて乗る経路が最適でも、その地点から実際に可能な最遅出発時刻であるため IDW に残す。舎人ライナー側も同様に残す。

## direct-component 比較実験について

`audit_physical_idw_exclusions.py` などで、unrestricted exact-point 経路と「その鉄道構成駅から直接乗ることを強制した経路」を比較する実験も行った。

この比較は、構成駅間の移動がどれだけアクセシビリティを改善するかを調べる研究用途には有用だが、production IDW の除外判定には使わない。

さらに、N02 `RailroadSection` から導出した隣接駅は **鉄道インフラのトポロジ** であって、旅客列車の運行系統・停車パターンそのものではない。JRの複々線・系統分岐などでは、インフラ隣接だけで「その物理地点から利用できる全旅客サービス」を列挙できる保証がない。このため direct-component 側の完全性判定にも使わない。

## production invariant

生成・検証コードでは次を不変条件とする。

```text
physicalPoints            = 1563
originVerified             = 1563
includedPhysicalPoints     = 1563
excludedPhysicalPoints     = 0
excludedStations           = 0
IDW grid stationCount      = 1563
IDW grid excluded count    = 0
```

この不変条件は `scripts/build_physical_station_dataset.py` と `scripts/validate_physical_station_dataset.py` で明示的に維持する。
