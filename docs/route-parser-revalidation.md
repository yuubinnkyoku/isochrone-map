# Yahoo経路パーサー全1563地点再検証

2026-09-09、地図上の浦和美園で、保存時刻は `07:12` なのに経路表示が
`徒歩1分 → 東京メトロ丸ノ内線池袋行 → 徒歩8分` となり、最初の鉄道乗車も
後楽園と誤判定されていることを確認した。

## 原因

Yahoo!乗換案内の保存済みルートには、鉄道サービス名が必ずしも `線` を含まない。
旧パーサーは主に `線` などを手掛かりに鉄道区間を検出していたため、例えば次の
サービスを見落としていた。

- `埼玉高速鉄道当駅始発武蔵小杉行`
- `東葉高速鉄道通勤快速中野行`
- `ＪＲ湘南新宿ライン大船行`
- `東武スカイツリーライン区間急行浅草行`
- `東武アーバンパークライン柏行`
- `ＪＲ特急しおさい4号東京行`

その結果、後段の別路線を「最初の鉄道」と誤認し、経路要約と
`boards-current-physical-point / boards-different-*` の表示診断が壊れていた。

加えて、国土数値情報側の `ヶ` とYahoo側の `ケ`（例: `西ヶ原` / `西ケ原`）を
別駅名として比較していたため、同一駅を「別駅へ移動」と誤判定するケースがあった。

## 修正

- 鉄道サービス検出語に `ライン`、`鉄道`、`特急` を追加。
- 文京区コミュニティバス `Bーぐる` をバスとして認識。
- 駅名比較時に `ヶ → ケ`、`ヵ → カ` を正規化。
- `classify_route1()` を分離し、保存済みの生 `route1` を現行パーサーで再解析可能にした。
- `build_physical_station_dataset.py` は、古い監査artifact内の分類結果を信用せず、
  毎回保存済み `route1` を現行パーサーで再解析してから `stations.json` を生成する。
- したがって今回の修正ではYahoo!へ1563回再問い合わせしていない。2026-08-28の
  元監査artifactに保存された同一の検索結果を再解析している。

## 全件再検証結果

元監査artifactの **1563 / 1563地点** を再解析した。

- 保存済み監査の診断が変わった地点: **177地点**
  - 先行する鉄道区間の見落とし修正: **139地点**
  - `ヶ / ケ` 等の駅名表記正規化: **38地点**
- 人間向け経路要約が変わった地点: **230地点**
- 再解析後の乗車地点診断:
  - その物理地点の鉄道から乗車: **1123地点**
  - 同一論理駅の別物理地点から乗車: **252地点**
  - 別駅へ移動してから乗車: **176地点**
  - 鉄道に乗らない: **12地点**
- 合計: **1563地点**
- IDW標本: **1563 / 1563**（この診断はIDW除外には使わない）

旧診断は `976 / 232 / 343 / 12` だった。特に「別駅へ移動」が343→176へ大きく減ったのは、
最初の鉄道区間を見落として後段の乗換駅を初乗車駅だと誤認していたためである。

## 浦和美園

修正後:

```text
浦和美園 07:12
徒歩1分
→ 埼玉高速鉄道当駅始発武蔵小杉行
→ 東京メトロ丸ノ内線池袋行
→ 徒歩8分
```

最初の鉄道乗車は `浦和美園 / 埼玉高速鉄道` と判定され、
`boards-current-physical-point` になる。

## 再発防止

最終データ検証では次を確認する。

- 再解析後の4分類が `1123 / 252 / 176 / 12` で合計1563。
- 浦和美園の最初の鉄道が埼玉高速鉄道である。
- `ヶ / ケ` 表記差の代表例が同一駅として判定される。
- 全1563地点で、保存された `firstRail.service` が人間向け `route` に含まれる。
- 全地点の `route` が空でない。
- IDW除外数は0のまま。
