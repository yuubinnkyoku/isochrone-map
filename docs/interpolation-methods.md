# 補間方法

駅マーカーの時刻は、1563個の物理駅地点それぞれについて Yahoo!乗換案内の `flatlon` で座標を固定し、08:18までに筑波大学附属高等学校へ着ける最遅出発時刻を再検索した実測値です。

地図上の駅と駅の間は実測値がないため、表示時には事前計算グリッドから補間します。現在は2方式を切り替えられます。

## 徒歩アクセス考慮（デフォルト）

任意地点 `x` の値を、各物理駅地点 `i` の最遅出発時刻 `t_i` から駅までのアクセス時間を引いた候補の最大値として近似します。

```text
T(x) = max_i [ t_i - 1.25 * d(x, i) / 80 ]
```

- `d(x, i)`: 地点と駅の直線距離（m）
- `80`: 徒歩速度 80 m/分（急ぎ足の近似）
- `1.25`: 道路が直線ではないことを近似する迂回係数
- 実効的には直線距離 64 m/分、約 3.84 km/h 相当の減衰

この方式では、ある駅から離れるほどその駅を使う候補時刻は必ず早くなります。同時に、別の駅へ近づけばその駅の候補が勝つため、駅勢圏の境界も自然に現れます。

これは pedestrian routing そのものではありません。河川、線路、崖、道路網、駅入口位置などを個別には考慮せず、直線距離に固定の迂回係数を掛けた近似です。駅地点そのものの時刻は Yahoo! の exact-point 再検索値が原データであり、このモデルは駅間の空間補間だけに使います。

事前計算は `scripts/build_access_grid.mjs` が行い、`data/access-grid.bin(.gz)` を生成します。1563駅を毎グリッド点で総当たりせず、KD-treeと「これ以上遠い駅は現在の最良値を超えられない」という上界を使って候補を枝刈りしています。

## 従来IDW

従来方式は Web Mercator 上の距離による逆距離加重平均です。

```text
T(x) = sum_i w_i(x) t_i / sum_i w_i(x)
w_i(x) = 1 / d(x, i)^2.5
```

駅地点の時刻を滑らかにつなぐには向いていますが、「駅から500m離れれば徒歩時間ぶん必ず不利になる」という意味は持ちません。比較・検証用として残しています。

## 表示との関係

「最適経路でこの地点の鉄道を使わない駅」の中抜き/強調表示と、補間方式は独立です。

- 駅マーカー: exact-point Yahoo! 再検索の実測値
- 中抜き等: その物理地点の鉄道を最適経路で使うかどうか
- 補間: 駅と駅の間の値をどう推定するか

IDW採否を変更するものではなく、1563物理駅地点は両方式の入力データとして保持します。
